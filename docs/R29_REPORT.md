## 一、演出音乐：实际游玩时为什么又短又轻

### 原因

演出音乐原来用网页的 `<audio>` 放，确认处决时跳到原曲 33 秒处（第二十七轮定的起点）。

| 实测（预览页面，同一个 `serve.py`） | 结果 |
|---|---|
| 向服务器要文件的头 16 个字节（分段请求 Range） | 回了 200 和整个文件，没有 `Accept-Ranges`——不支持分段请求 |
| `<audio>` 能跳着放的范围（`seekable`） | 0–0 秒 |
| 让 `<audio>` 跳到 33 秒 | 还在 0 秒 |

- 开发服务器（`serve.py`，Python 自带的 http.server）不支持分段请求，浏览器就不让 `<audio>` 跳着放：跳到 33 秒的那一下被丢掉，实际从原曲开头放。
- 原曲开头这几秒（逐秒的平均响度）：0 秒 −36.6 dB、1 秒 −28.3 dB、2 秒 −21.4 dB，3 秒起才到 −14 dB 上下，而且是另一段旋律。所以开头像是没有音乐，之后又不是该有的那段——听着又短又轻。
- 录像的配音是离线按文件从 33 秒混的（`tools/r19_mix_audio.py`），所以录像里是对的。第二十七轮的自检只核对「叫了从 33 秒放」，没有核对实际放到了哪里，也就没发现。

### 播放速度

一直是一倍速：
- 原来的 `<audio>` 每次放之前都设了 `playbackRate = 1`；
- 原曲是 48 千赫的双声道，没有被当成别的采样率放。

### 改法（`src/core/audio.js` 的 `cue*`）

- 载入游戏时取回整首（143.856 秒）、解码，只留原曲 33 秒起的 24 秒（演出用到约 16 秒）。整首解码约 55 MB，截下的一段约 9 MB。
- 演出时用声音时钟从这一段的开头放，与服务器支不支持分段请求无关；暂停后由同一处接着放。
- 时机：在山水铺开之前 0.1 秒进（`FINALE.music.cueAt = 0.5`，山水铺开在演出 0.6 秒），0.1 秒淡入。
- 一直放到退场（15.6 秒），再 0.5 秒淡出：由进到淡出完 15.58 秒。
- 收刀合拢前后、龙凤砸入时让开一下，与第二十七、二十八轮相同。

### 实测

| 项 | 结果 |
|---|---|
| 进的时刻 | 演出 0.517 秒（0.5 秒之后的第一帧） |
| 进的那一刻在原曲里的位置 | 33.005 秒 |
| 暂停后续放的位置 | 演出 5.35 秒恢复 → 原曲 37.85 秒（= 33 + 5.35 − 0.5） |
| 淡出 | 演出 15.6 秒起 0.5 秒 |
| 实时（墙上的钟走 3.007 秒） | 音乐在原曲里走了 3.000 秒（0.998）——一倍速；后台标签页的计时本身有几毫秒的出入 |
| 三段录像里音乐进的时刻 | 都是各自演出开始之后 0.5 秒 |

## 二、演武场

以前 `whyNot()` 里写着「切磋对手点到为止」，切磋对手一律不处决（`config`）。现在与别的敌人一样：任何招式的致命一击都放演出，满蓄力拔刀斩剩 ≤ 10% 也能处决。

| 做法 | 说明 |
|---|---|
| 切磋对手的接口（`DUELIST`，`src/game/inkFinale.js`） | 停手：对手的 AI 停在 `finale` 态，不出招、不走位；演出中的姿势同魔修（失衡、慢慢定住）；收刀合拢时走战斗系统的正常结算把他击倒 |
| 演出中演武场停住（`arena.update`） | 计时、对手的 AI、圈边的拦挡（会把玩家拽回圈里）都不走，由演出摆双方的站位 |
| 站位在比试圈里（`arena.inRing`） | 演出挑玩家站位时，几处都要离圈边至少 0.6 米 |
| 胜负等演出交还之后再出（`arena.finaleDone`） | 收刀时击倒的，演出交还之后才判胜：画面中央的「胜」、1.8 秒后的结算面板；自由练习交还之后 1.8 秒复原 |

| 自检 | 结果 |
|---|---|
| 正式切磋（`arenaRun29('formal')`） | 致命一击被接过（`exec`）；站位 full，玩家的三处站位都在圈里；演出中对手没有出手、切磋计时没走（0 秒）、玩家没掉血；交还之后判胜，对手 `defeated` |
| 自由练习（`arenaRun29('free')`） | 同样放演出；交还之后对手复原（气血 336 / 336） |
| 满蓄力拔刀斩（`arenaIaiRun`） | 对手剩 8%：处决（来路 `iai`），交还之后判胜 |

录像里交还之后，被击倒的对手照常显出（演出中途按层藏起，交还时还原：层掩码 1，镜头看得见），躺在圈里。

## 三、通用的终结

### 规矩

| 情形 | 结果 |
|---|---|
| 只有一个敌人，用任何招式打死它（普攻、剑诀、拔刀斩、凤凰、雷龙、剑气、反弹回去的投射物） | 放演出，不需要墨势 |
| 群战，打死的不是最后一个 | 照常倒下 |
| 群战，一下（群伤）打死好几个 | 只有最后一个放演出 |
| 首领（第三十层、第五十层）的前几条命打空 | 照常转阶段 |
| 首领、分段敌人的最后一条命打空 | 放演出，收刀时胜利 |
| 护宗双龙打死的、来路不明的持续伤害 | 照常倒下（不算玩家一方的击杀） |
| 御剑中、演出素材没就绪 | 照常倒下 |

- **「群战里的最后一个」**（`isLastFoe`）：同一场景里，除了它自己，没有别的活着、敌对、还在这场战斗里的敌人。
  - 首领、切磋对手都算在这场战斗里；
  - 交过手的（被打过、在追击 / 进攻 / 受击）在玩家 60 米内算；
  - 没交过手的，在 30 米内、没有沉睡的也算（`FINALE.kill.radius`）。
- **玩家一方**：玩家自己，玩家的凤凰、雷龙（`ownerPlayer`），玩家的剑气与反弹回去的投射物（`owner: 'player'`）。
- **这一下不扣血**：最后一个敌人在演出收刀合拢（13.2 秒）时才倒下，修炼灵气、任务计数也在那时结算。
- **跳起来打死的也演**：化墨之后在地面上凝聚；御剑中不演。

### 接在哪里

- `combat.damage`：这一下已被接受（没被无敌拒绝）、确定会致命、扣血之前，问 `finale.lethalProbe`；接过了就返回 `exec`，不扣血。
- 第三十层、第五十层首领的 `receive`：最后一条命打空的那一下同样先问。
- 分段的敌人（试炼魔将）：前几段打到本段的底照常转段（`notFinal`），最后一条命才问。
- 满蓄力拔刀斩的处决（`whyNot`）也加了这两条：还有别的敌人时 `notLast`，首领的前几条命 `notFinal`。

### 自检

| 组 | 检查 | 结果 |
|---|---|---|
| killSolo | 一个敌人，不给墨势：普攻（真实按键，第一式 `light1` 打死）、凤凰、雷龙、玩家的剑气打死——都放演出（来路 `kill`），收刀时倒下；护宗双龙、来路不明的持续伤害打死——照常倒下 | 通过 |
| group | 依次打死三个：前两个照常倒下（`notLast`），第三个放演出；一下打死三个：前两个照常倒下，最后一个放演出；45 米外没惊动的敌人不拦着，12 米外没惊动的拦着 | 通过 |
| iaiRules | 满蓄力拔刀斩：旁边还有一个敌人时不处决（`notLast`），照常吃强化伤害（扣 348）；只剩它一个时处决（来路 `iai`） | 通过 |
| stagedKill | 试炼魔将：第一段打到底照常转段（`notFinal`，停在 260、进第二段）；最后一条命打死放演出 | 通过 |
| bossKill | 第三十层、第五十层：一阶段打空照常转阶段（`notFinal`）；二阶段打空放演出，收刀（13.2 秒）时整场胜利 | 通过 |
| abyss | 幽渊秘境（地下场景）里也演：画中世界照常铺开（演出 3 秒时替换了 157 个原场景物体），收刀时倒下，换回宗门 | 通过 |
| cleanup | 连续两次通用的终结之后：镜头、控制、界面、音乐（`idle`）、演出物都复原；几何体、贴图数不增加 | 通过 |

## 四、规矩的变化，与改了期望的旧自检

- 满蓄力拔刀斩的处决（剩 ≤ 10%）也只在群战的最后一个、首领的最后一条命。
  - 以前首领的非最终阶段也放演出、只结束当前阶段；现在照常转阶段，不放演出。
- 墨势仍然有用：
  - 满蓄力拔刀斩刀身 ×2；
  - 最后一个敌人剩 ≤ 10% 却没被这一刀打死时，也直接处决。

按旧规矩写的几组自检改了期望，每处都注了「第二十九轮」：

| 自检 | 旧期望 | 新期望 |
|---|---|---|
| r25 `thresholdRun` | 剩 11% 的寻常魔修被强化一刀打死：照常倒下 | 拔刀斩不处决（`hp`），但只剩它一个——走通用的终结放演出（来路 `kill`） |
| r25 `primaryRun` | 三个都在刀下，锁定的低血量主目标处决 | 目标气血调高（打不死），主目标照旧这么选；还有别的敌人在，不处决（`notLast`） |
| r25 `protectRun` | 第二个敌人在 6 米外 | 放到 35 米外、没惊动（否则第一个不是最后一个，不放演出） |
| r27 `stagedRun` | 试炼魔将第一段处决（演出、只结束第一段） | 第一段不处决，照常转段；第二段处决 |
| r27 `bossRun` | 第三十层、第五十层一阶段也放演出 | 一阶段不放（`notFinal`）；二阶段放（另加了第五十层二阶段） |
| r27 `framingRun` | 首领的构图在一阶段量 | 在二阶段量 |
| r27 `musicRun` | 演出音乐在确认的那一刻起；没有墨势的拔刀斩打死 8 气血的魔修，不起音乐 | 在 0.5 秒起，续放的位置按 0.5 秒算；目标调成打不死（打死只剩的一个会放演出） |
| r28 `harmlessRun` | 满蓄力拔刀斩处决，2.7 米外另有一个魔修 | 那个魔修设成沉睡（不算这场战斗里的），用一下致命一击触发 |
| r24 `cineRun('victory')`、`retryRun` 第三轮 | 二阶段剩 1 气血时一刀打死，紧接着看胜利过场 / 胜利后的状态 | 最后一条命先放墨里终焉的演出——像玩家一样按跳过，再看胜利过场与胜利后的状态 |

## 七、没做完 / 限制

- **音乐没有实听**：只按声音时钟量了起止、位置与速度。预览是后台标签页，我听不到声音。
- **`serve.py` 仍不支持分段请求**：游戏已不依赖它，没有改服务器。
- **最后一个敌人的结算晚了**：收刀合拢时才倒下、才发修炼灵气，比以前晚约 13 秒。
- **一个人游荡的魔修，打死一个就放一次**：每次 16 秒，可以随时按空格 / E 跳过。
- **「最后一个」按距离与状态判断**：30 米外、没惊动的敌人不拦着，所以大地图上远处还有敌人时也会放。
- **旧录像的规矩已过时**：第二十七、二十八轮的 `r27_b30p1.mp4`、`r28_b30p1.mp4` 里第三十层一阶段放了演出，现在一阶段照常转阶段。
- **别的旧自检**：第十七、二十一、二十二轮的自检这轮没有重跑；里面若有「打死最后一个敌人后立刻核对」的，现在要等演出收刀（或先跳过演出）才对得上——第二十四轮就有两处是这样，已改。
