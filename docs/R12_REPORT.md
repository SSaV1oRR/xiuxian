# 第十二轮：问道殿外观、灵池花树与落樱

本轮的要求原话是：「问道殿的外观看我 assets 里 building 里是否有可以使用的素材，现在的不好看，灵池的院子里要有至少 10 棵粉色的树，以及哇棵黄色的树，并且要实现落樱飘落的视觉感」。

拆成三件事：

1. 问道殿外观：先看 `assets/buildings` 里有没有能用的素材，再改好看。
2. 灵池院：粉色的树不少于 10 株；黄色的树「哇棵」。「哇」与数目对不上，按读音最近的「五」理解，种到 5 株。
3. 落樱：要看得出花瓣在飘落。

改动的文件：
- 问道殿外观：`src/world/arch/tower11.js`、`src/world/arch/arch.js`、`src/world/arch/builder.js`
- 灵池花树：`src/world/layout.js`
- 落樱：`src/world/petals.js`、`src/main.js`
- 署名：`src/game/game.js`（游戏内致谢）、`README.md`

没有新增外部素材。改动前的整个项目备份在 `backups/xiuxian-r11-20261008-0415.zip`。

## 1. `assets/buildings` 里的素材

`assets/buildings/` 只有一个 `01.fbx`（3d66 模型网导出的古城街）。第十轮已经从里面拆出 8 种古建，全部用在宗门里：凌云阁、藏经阁、丹殿、两座配殿、膳堂、两处院舍、钟鼓楼与阙楼；原来的问道殿（素材 D）第十一轮换成五层楼阁后就不再使用。

能不能拿其中一栋直接当问道殿？不行，原因如下：

- **尺度**：问道殿首层是 46 × 44 米、五层，素材里最大的一栋楼阁不到 20 米宽。放大到 46 米宽是 2.3–4.6 倍，门会变成 5–9 米高，瓦垄一垄一米多宽，踏步半米高。第十一轮定下的「门窗、瓦、踏步按真实尺寸，不整体缩放」就保不住了。
- **结构**：殿内五层要能走，外观的门窗洞要与殿内一一对应（尺寸都在 `hallSpec.js`）。素材楼阁的层高、开间、窗洞都对不上。

所以这一轮没有换模型，用的是素材的**手绘贴图**。这些贴图随 `buildings.glb` 载入，共 16 张：003 是 2048²，其余是 1024²。它们是按横条排的图集，每条一种构件：
- 瓦垄、带瓦当的檐口一行
- 封檐板、椽子
- 回纹带、描金额枋、彩画垫板
- 隔扇门、菱花窗、栏板
- 灰泥墙
- 山花

宗门里其他素材殿阁用的也是这一套贴图，问道殿换上后画法就统一了。

## 2. 外观改动

### 2.1 贴图怎么贴：按米循环，不拉伸

`builder.js` 的 `tr*` 材质在着色器里从图集取一条，横向每隔若干米循环一次。纵向有两种取法：整面贴满一次，或者也按米循环。瓦面另有「檐口一行」，自檐口起取一次带瓦当的那一行，其上才循环瓦垄。

取样有三点处理：
- 用 `textureGrad` 按实际的屏幕导数选 mip，循环接缝处不会闪。
- 像素框向内收 2 像素，不渗到图集里相邻的块。
- 每种材质可设亮度倍数（默认 1.16，与第十轮素材建筑一样提亮）。

| 材质 | 贴图 | 像素框 [x0, y0, x1, y1] | 循环 | 用在 |
|---|---|---|---|---|
| `trTile` | 017 | 瓦垄 [0, 6, 1024, 206]；檐口一行 [0, 292, 1024, 556] | 横 3.2 米、纵 0.62 米，檐口行 0.82 米 | 腰檐、上下檐、抱厦的瓦面 |
| `trRafter` | 016 | [0, 380, 1024, 432] | 横 3.9 米、纵 0.6 米 | 檐下椽子（背面） |
| `trFascia` | 016 | [0, 2, 1024, 46] | 横 3.6 米 | 封檐板、仔角梁、博风板 |
| `trSill` | 013 | [0, 598, 1024, 868] | 横 3.8 米 | 槛墙 |
| `trPlank` | 013 | [0, 748, 1024, 860] | 横 2.6 米 | 窗洞两侧竖板壁 |
| `trHead` | 016 | [0, 652, 1024, 784] | 横 4.6 米 | 窗上回纹带与额枋 |
| `trBeam` | 016 | [0, 708, 1024, 782] | 横 4.2 米 | 朱漆描金额枋、平座台面 |

### 2.2 檐角：只在角上陡翘

原来的起翘范围按屋面宽的 26% 算。腰檐宽约 50 米，起翘就摊在角上十三米的长度里，远看几乎是平的。这正是看上去「笨重、像一摞盒子」的主要原因。

这一轮给 `liftFn` 加了「起翘范围」参数（米，自檐角起算），屋面、角脊、封檐板、宫灯挂点都按同一条曲线：

| 位置 | 起翘范围 | 角上翘起（原来） |
|---|---|---|
| 一至四层腰檐 | 6.5 米 | 1.45 米（0.85 米） |
| 顶层下檐 | 6.5 米 | 1.6 米（1.0 米） |
| 顶层上檐 | 8 米 | 2.2 米（1.6 米） |
| 抱厦 | 4.2 米 | 1.2 米（0.95 米） |

给定起翘范围时，屋面沿檐方向加密网格，每段不超过起翘范围的五分之一，翘起的那一段是顺的，不是折线。不给这个参数的屋顶（宗门里其他程序化建筑）照旧。

### 2.3 仔角梁

每个檐角挑出一根渐细、上翘的弯木，木色与封檐板相同，梁头一颗鎏金宝珠。素材殿阁上高高翘起的檐角尖就是这个样子。

- 基本尺寸：挑出 1.5 米，上翘 1.15 米，粗 0.2 米收到 0.045 米。
- 按各檐大小缩放：腰檐 0.85、顶层下檐 0.95、顶层上檐 1.25、抱厦 0.75。抱厦只做前两角，后两角在殿身墙里。

原来角脊端的小鎏金卷草由梁头宝珠代替。封檐板由 0.36 米加高到 0.5 米。

### 2.4 立面：粉墙与菱花窗

- 每层角间的实墙原来画的是关着的隔扇门（暗红），改为灰泥粉墙。槛墙与额照旧。一至四层的四角，加上一层北面中间三间，都变成浅灰。
- 关着的槛窗、开着的窗扇原来是暗红雕花窗，改为米黄窗纸的菱花窗。入夜窗纸亮处透出灯光。
- 立面因此有了明暗层次，不再是一整片暗红。

### 2.5 顶层：十字脊

上檐由一座歇山改为十字脊：方形屋面（35.6 米见方）上两座歇山十字相交，四面各见一座山花，脊心是鎏金宝珠，四个脊端各一只鸱吻。

实现：
- 第一座照常画。
- 第二座转 90°，只画上部两坡与山花（`xieshanRoofGeo` 的 `upper` 选项）。它的下部四坡、戗脊与第一座完全重合，不画就不会深度冲突。两座上部两坡的高度剖面相同，交线正好在对角线上。

山花贴素材的山花图（朱红底、鎏金卷云），uv 归一到整面一张。斜边加 0.75 米高的博风板，悬鱼放大到 2.4 倍。抱厦的山花也换成同一张图，加博风板。

### 2.6 没有动的

- 尺寸：五层的面阔、进深、层高、开间。
- 门窗洞：位置与大小都没改，仍与殿内一一对应。
- 碰撞、殿内场景、进出殿。
- `bayFill` 只用于外观。殿内用的是自己的 `bayIn`，室内看出去的窗扇就是外观这一份。

## 4. 落樱

### 4.1 原来为什么看不出来

第六轮以来的做法是：附近 80 米内所有花树一共每秒落 70 片，花瓣池 520 片，花瓣只有 9 × 7.5 厘米。近处几十株花树分下来，每株每秒不到两片，又小，所以几乎看不见在落。

### 4.2 现在的做法（`petals.js`）

- **花瓣**：16 × 13 厘米，每片再随机 0.8–1.3 倍；颜色樱粉，透光。
- **哪里落得多**：
  - 20 米内的花树权重 8，40 米内 3，80 米内 1。
  - 每秒新生 20 + 20 × (25 米内花树数) + 2.5 × (60 米内花树数) 片，平时上限为花瓣池的 1/14。
  - 灵池院里站着时，花瓣池常常全部在用。
- **从哪里落下**：
  - 镜头前：附近有花树时，约三分之一的花瓣生在镜头前方 3–14 米、左右各 7 米、高出镜头 1.5–6 米处，直接从画面里飘过。殿内不生成，免得花瓣出现在殿里。
  - 上风处：一部分花瓣从上风处高 3–7 米飘来。
  - 树冠：其余从附近的树冠里落下。
- **飘落**：下落速度每秒 0.5–0.9 米，打着旋、左右摆荡、随风斜飘。风向缓慢转动，时强时弱。
- **阵风（花吹雪）**：
  - 每隔 14–26 秒一阵，0.8 秒起势，持续 2.5 秒，2.2 秒平息。
  - 阵风里风速加到 3.4 倍，新生花瓣加到 4.5 倍（花瓣池有空位时），飘着的花瓣先被托起、翻得更快、斜着飞。
  - 已落地的花瓣贴地滑开。
- **落地**：停 3 秒，再用 2.5 秒缩没。
- **落水**：用 `terrain.waterAt` 判断。落进水里的花瓣浮在水面，随风缓缓漂开、随波起伏，漂到岸边就停；9 秒后 3 秒内隐去。
- **水面落花**：临水的樱花树下，水面另铺一层静态的落花，离岸至少 1.3 米。着色器里每片绕原处漂一个小圈、轻轻起伏，不占 CPU。灵池里均衡画质 301 片，流畅 130 片。
- **花瓣池**：均衡 2000、精美 3000、流畅 900（原来 520 / 700 / 260）。

### 4.3 开销

花瓣池 2000 片全部在用时（灵池院内），每帧逻辑约 0.5 ms，平时与阵风时差不多。帧时的整体影响见第 6 节。

## 6. 性能（实测）

条件与前几轮一致：均衡画质，1600×900，像素比 1，9:30，`tools/perf_r9.js`（预热 30 帧，两轮各 30 帧取较好的一轮，每轮末 `gl.finish`），同一台机器。每格为每帧 / 三角形 / 绘制调用：

|---|---|---|
| 接引院 gate | 12.2 ms / 5.04M / 803 | 13.7 ms / 5.19M / 817 |
| 前庭 fore | 13.8 ms / 5.23M / 842 | 8.5 ms / 5.35M / 851 |
| 演武广场 plaza | 12.3 ms / 4.74M / 674 | 11.5 ms / 4.88M / 693 |
| 藏经阁 lib | 7.5 ms / 4.26M / 579 | 8.2 ms / 4.35M / 585 |
| 竹院 dorm | 12.3 ms / 4.52M / 627 | 7.8 ms / 4.56M / 644 |
| 丹殿 alch | 8.7 ms / 4.56M / 619 | 9.2 ms / 4.75M / 644 |
| 灵池 pool | 9.0 ms / 3.99M / 485 | 7.9 ms / 4.20M / 488 |

| 后山 backhill | 6.9 ms / 3.29M / 327 | 6.7 ms / 3.43M / 330 |

- **灵池**：多了约 0.2M 面（13 株花树与水面落花），帧时没有变长。
- **云顶**：三角形数与第十一轮相近（3.45M 对 3.52M）。外观在檐角加密了网格，加了仔角梁与十字脊，增加的面数不多。

本轮没有为了性能降低任何模型或贴图的精度。

## 8. 限制与说明

- **「哇棵」**：按「五棵」理解，种了 5 株金黄银杏。如果原意是别的数目，改 `layout.js` 里 `KEY_TREES` 灵池一段即可。
- **贴图精度**：素材贴图是 1024²（003 为 2048²），按米循环，远看、中看都清楚。贴着墙看（3 米内）比第十一轮的程序化细部略软。山花那张图只有 240 × 185 像素，铺在 14 米宽的山花上，近看偏糊。
- **山花构图**：山花图是长方形的，铺在三角形上，卷云两端会被斜边切掉一点，一部分由博风板挡住。
- **十字脊**：两座屋面直接相交，交线处没有另做窝角沟的瓦。
- **花瓣落点**：只按地形高与水面判断落地，落在屋顶、桥面、檐上的花瓣会穿过去落到下面。
- **阵风效果**：灵池院里花瓣池常常全部在用，阵风时主要是飘着的花瓣被吹得翻飞斜飞，新生的会少一些。
- **溢水渠**：东岸的溢水渠把环池步道截断（第九轮起就是这样），这一轮没有在渠上加桥。
- **镜头前的树冠**：镜头与人物之间的树冠会打点淡化，好让人看到角色。这是原有的做法，截图挑了没有遮挡的机位。
