# 第二十五轮报告：拔刀斩-终式·墨·终焉

本轮把拔刀斩升级为「拔刀斩-终式·墨·终焉」。沿用现有的部分：
- 人物、手中的剑与鞘；
- 拔刀斩的动作与判定；
- 战斗结算（`combat.damage`）；
- 剑诀栏与装备槽、等级成长、存档；
- 凤凰、雷龙的模型与两组水墨贴图。

没有另起一套战斗或输入系统。`combatConfig.js` 一行没动，其他剑诀（包括普通拔刀斩自己的数值）的平衡不变。

全部参数在 `src/game/inkFinaleConfig.js`（`FINALE`），见 §4。

下文的数字都出自页面里按真实输入、出招、结算与演出代码推进的自检：
- `tools/r25_tests.js`：`runAll({ boss: true })` 23 组一次跑完，约 40–75 秒（后台标签页，随机器负载起伏）；
- 录像出自 `tools/r25_film.js`。

改动前备份：`backups/xiuxian-r24-20261011-1043.zip`。

## 2. 真实素材：清点结果与动作对应

先清点再动手。脚本在 `tools/r25_inventory_*.py`（Blender 5.2.2 后台导入后实测），数据存在页面外。

### 2.1 清点（实测）

**单手剑动作包 `assets/fighting/One Handed Sword Animation V5 FBX`**
- 文件与动作：
  - 342 个 FBX（IP 161 + RM 181），共 190 段不同的动作；
  - 152 段两套都有，9 段只在 IP（Idle1–3、Jump 四段、Sheath、Unsheath），29 段只在 RM（Dash、Dodge、Roll、Hit、Death 各向）。
- 格式：全部每秒 30 帧，88 根骨（UE5 Manny 骨架），两种导入器的帧率、帧范围、根位移一致。
- 根运动：根骨从不转动、从不上下，只有水平位移；骨盆在水平方向锁在根上。IP 版并不完全原地，根在片段内最多漂 0.30 米。
- 循环：16 段 Loopable 首尾差 ≤ 2.7°；另有 61 段首尾相同（< 5°）。
- **Sheath（纳刀）/ Unsheath（拔刀）**：各 24 帧、0.767 秒，Unsheath 就是 Sheath 倒放（逐帧最大差 3.7°）。Sheath 的分段：
  - 0–0.333 秒：右手由身侧低处挥到最高点；
  - 0.333–0.467 秒：沿刀身方向推入，0.49 米；
  - 0.467–0.500 秒：「一合」——手几乎停住（0.38 米 / 秒），拳在这一帧开始松开；
  - 0.500–0.767 秒：空手甩回，片段结束时仍在动（1.83 米 / 秒）。

## 3. 规则怎么落实（按需求各节）

### 3.1 位置与输入（一）

- **不是新格子**：终式就是拔刀斩那一格（默认 R）。
- **解锁**：不看等级直接解锁，存档 `skillUp.power = { form: 'inkFinale', unlocked: true, at, why }`。原有进度、剑诀装备、冷却都不重置。
- **按键**：槽键、Z、鼠标中键三个入口共用一个技能入口、一份蓄力。同一次蓄力只认最先按下的那个，别的键按下、松开都不算（`loadout.claimPower` / `releaseSrc`）。
- **卸下即失效**：卸下拔刀斩后，槽键、Z、中键、旧的剑诀栏按钮、直接调用 `moves.press('power')` 都放不出来。
- **墨势条件**：没有墨势、或有墨势但没蓄满 3 秒，就是普通拔刀斩。判定沿用拔刀斩的刀身判定，不另加范围。
- **界面**：
  - 剑诀栏这一格标「终式」，悬停写「拔刀斩-终式·墨·终焉（R、Z、鼠标中键）」；
  - 剑诀面板分开写「普通释放」与「墨势满蓄力释放」，并写明墨势规则与「不耗灵力 · 无调息」。

### 3.2 墨势（二）

- **计数与去重**：普攻四式（`light1–4`）结算完，交给 `onLightStrike`。
  - 这一刀里，结算结果是 hit / guardbreak、结算前活着、敌对、可受击的目标，至少一个，就计 1。
  - 按「攻击实例号 + 段号」去重，一刀打中几个、跨几帧都只计一次。
- **不算的**：剑诀、召唤物、持续伤害、弹反的自动效果根本不走这个入口。
- **超时**：用战斗时钟，打开界面、演出、首领过场时不走。没成势时满 8 秒清零。
- **成势之后**：不超时；多出的命中只记在统计里（`overflow`），不预存。
- **清除**：力竭、重试、离开、换场景时清除，换一个新的战斗实例号；墨势与计数不存档。

### 3.3 蓄力与消耗（三）

- **满蓄力**：有墨势时 `iaiCharge.full = 3` 秒；满了保持就绪，不自动出刀。普通拔刀斩仍是蓄满 5 秒再撑 1 秒自动出刀。
- **正式出刀**：松开时，若有墨势且蓄力 ≥ 3 秒，`formalDraw` 一次做完：
  - 验证；
  - 消耗墨势、计数回 0；
  - 费用与冷却（拔刀斩本来就不耗灵力、没有调息，所以都是 0）；
  - 生成唯一的攻击实例。
- **不消耗的情况**：不满 3 秒、取消（格挡 / 闪身）都不消耗。空挥照样消耗、不返还。
- **打断**：受击、力竭、打开界面时，蓄力与按住的状态清掉，不留待放的输入。

### 3.4 伤害与主目标（四）

- **强化伤害**：刀身那一下的技能倍率 `FINALE.dmgK = 2`，在现有伤害流程里乘一次。之后照常乘等级成长、反击强化、目标防御；出刀的其余各量（范围、失衡、击退、削架势、剑气）按满蓄力取，剑气不吃这个倍率。
- **主目标**：先收齐这一刀这一帧真实接触到的一批目标——
  - 锁定的目标在其中就是它；
  - 否则取刀轨上最先碰到的（按扫到的先后，同时碰到按生成顺序）；
  - 选定后记在这次出刀上，不再改。
- **只判一次**：主目标只做这一次处决探针（`fin.probed`）。不合格就不再找别的低血量目标，其余目标照常 ×2。
- **被拒绝的情况**：主目标的这一下被格挡、弹反、无敌拒绝时，根本到不了探针，记为 `rejected`。

### 3.5 处决资格与阶段比例（五）

- **条件**（`whyNot` 依次查，原因记在出刀记录里）：
  1. 玩家活着（`playerDead`）；
  2. 目标活着（`dead`）；
  3. 敌对、不是木人桩（`notHostile`）；
  4. 不是切磋对手或友方（`config`）；
  5. 没被别的处决占着（`occupied`）；
  6. 首领配置允许（`config`）；
  7. 这一阶段能被结束（`stageLocked`：不在开战前、过场中、剧情保护中）；
  8. 当前阶段比例 ≤ 10%（`hp`）。
- **阶段比例**（`stageRatio`）：
  - 独立血条：本阶段气血 / 本阶段上限；
  - 共享阈值：(气血 − 本阶段终点) / (本阶段起点 − 本阶段终点)，限在 0–1。
- **处决与否**：合格就处决，探针返回 `exec`，这一下不扣血、不算强化伤害。不合格就照常 ×2。
  - 这一下把它打进 10% 以下也不补处决；
  - 打死就是普通的死亡；
  - 一次出刀最多处决一个。

### 3.6 记录与结算（六）

- **唯一记录**：战斗实例号、攻击实例号、玩家、目标、阶段、状态（confirmed → committed / invalid）、是否已提交。
- **确认时**：
  - 目标 `finaleLock`：不吃别的伤害、不出招、不被别的处决或凤凰秒杀选中；
  - 首领 `finaleHold`：整场停住，危险物停在原处；
  - 玩家 `finaleGuard`：不受伤。
- **提交**：只在收刀合拢的一刻（完整演出约 6.8 秒、精简约 3.05 秒），或跳过时走同一个入口 `commit(src)`，只提交一次：
  - 寻常敌人：`combat.damage` 的正常死亡（奖励、计数照旧）；
  - 首领：`executeStage({ finale: true })`。非最终阶段只结束这一阶段，转阶段过场延到演出交还后放；最终阶段照常胜利，奖励只发一次。
- **退回**：确认前先定方案（完整 → 精简）。都不成就记 `noShow`、`fallbacks + 1`、打一条 `console.info`，这一刀按强化伤害结算，不锁目标。

### 3.7 演出期间（七）

- **整个世界停住**：主循环里，演出接管时，敌人、首领、召唤物、冷却、持续伤害、回血的时钟都给 0；`combat.update` 换成只更新界面层。
- **时钟**：只推进演出自己的时钟与玩家。菜单、失焦、后台时主循环给 0，演出停住，回来不补算。
- **其他目标**：同一刀打中的其他目标只在出刀那一下结算一次。

### 3.8 完整演出（八）

时间轴见 README 的表，都在 `FINALE.full`。另外几点：
- **对准真实动作**：收刀从 3.2 秒起放 `iai_noto`，合拢的时刻由它的 close 标记推出（3.2 + 3.6 = 6.8 秒），不是写死的定时。三种帧率下提交时刻分别为 6.833 / 6.817 / 6.806 秒（§5 第 19 条）。
- **站位按尺寸**：用目标的身体半径与高度。身后起点在身子外 2.4 米，缓步到 1.25 米处拔刀，穿过后停在身前 2.3 米。
- **路线检查**（每 0.25 米一个采样点）：
  - 地面要连续：相邻高差上 0.46 / 下 0.7 米，整条不超过 1.2 米；
  - 不在深水里；
  - 离墙、柱至少 0.42 米：用碰撞世界推一个圆，被推开就算墙；
  - 0.5 米、1.25 米两个高度的墙体射线；
  - 墨痕绕后的那一下不穿墙；
  - 不出场地边界。
  
  正对的轴线不合法时，依次偏 ±25°、±50° 再试；都不行就改精简演出，原因记为 `wall` / `cliff` / `noGround` / `bounds` / `water`。
- **唯一的位移驱动**：演出期间玩家的位置只由 `Show.setPos` 给，不经人物的根运动与碰撞推挤。结束时停在身前的落点 F，不瞬移回原处，不改任何碰撞。
- **画卷**：卷轴向前滚动铺开，有卷边、纸纹、两侧裱绫、晕染与流动的笔线。画卷按地面逐段采样高度贴地，相邻高差超过 0.22 米处撕开。
- **山水**：远、中、近三层画在围着敌人的环带上，各有视差与山脚的雾。远山在流畅画质里不画。演出结束即撤。
- **刀与鞘**：用手中真实的剑与鞘，不另造武器；演出期间只隐藏一次（化墨时），没有第二把刀。
- **龙凤**：都是独立的演出实例，几何与骨骼克隆，材质另做一份水墨版，原技能的材质不动——连续三次后材质名仍是 `phoenix-r21` / `loong-r23` 与 `phoenix-ink-r25` / `loong-ink-r25`（§5 第 18 条）。
  - 起点、控制点在演出镜头的坐标里定：凤凰在画面左后（侧 −7.5、后 9.5、高 4.6 米），雷龙在右后（侧 8.5、后 12、高 6.2 米）。

- **交还时**：`lastAction` 置为很久以前、`drawn` 归零——要重新按下左键才出手，按住的左键不会自动续打。

- **作废**：重试、离开、换场景时，`newInstance` 把记录标为 invalid，不提交伤害与奖励；清掉保护、暂停、镜头、界面与临时实例。已消耗的墨势不返还。清理可重复调用。

### 3.13 配置与性能（十二）

- **集中配置**：参数都在 `FINALE`（§4）。
- **预热**：
  - 进入场景时：`InkFinaleFx.prewarm` 把演出物全部临时摆出来编一次着色器；
  - 会投影的演出物（卷轴、轴头、凤凰、雷龙）的阴影着色器，在接下来真画的那一帧里编好（放在镜头下方 200 米、颜色深度都不写，画面上看不到）；
  - three.js 的着色器变体随场景里的灯数而变，所以满蓄力的那一刻再预热一遍投影。
- **对象池**：粒子用对象池；临时实例结束即撤，共享资源不销毁。
- **流畅画质**：远山一层不画；粒子池 320（原 720）；墨带 4 条（原 7）；碎片 12 片（原 26）。人物动作、真实的刀、龙凤、八卦阵与终结刀光都保留。实测见 §8。

## 6. 本轮发现、已修好的问题

1. **方法名被同名字段遮住**：`InkFinale` 的构造函数里写了 `this.post = post`（调色），遮住了同名方法 `post()`，主循环报 `finale.post is not a function`。字段改名 `postFx`。
2. **演出卡在定格里不结束**：定格时把演出时钟也停了。改为演出时钟总在走，只有画面与人物用定格后的 dt。
3. **画卷网格错乱**：`PlaneGeometry` 的顶点是按行排的（顶点号 = 行 × (列数 + 1) + 列），先前按列算。
4. **山水上下颠倒**：画布贴图上传时已经翻过一次，着色器里又翻了一次。
5. **山水像一面暗幕**：
   - 重画成一组组山峰，留出空白；
   - 环带加高，近层山脚融进雾里。
6. **其他画面问题**：墨溅像黑球、光晕太大、碎片方块化——都换了贴图与尺寸。
7. **NPC 挡住穿行镜头**：演出时藏起 20 米内的 NPC，结束后复原。
8. **雷龙撞入后扫过玩家**：改为向下潜入，同时加快消散。
9. **暗场景里八卦、墨带看不出来**：第三十层、第五十层的地面是暗红 / 暗紫，墨色画在上面几乎看不见。改为按场景暗度把笔画翻成墨芯银边。
10. **鞘口墨环看不见**：原来是黑鞘上一圈黑墨，又贴着鞘面，被鞘身与鞘口的金饰挡住。
    - 加银白飞白边；
    - 环比鞘粗一圈、离开鞘面。
11. **演出中现编着色器（卡顿）**：第一次演出时，画卷出现（0.52 秒）、龙凤出现（3.3 秒前后）各现编一个投影用的深度着色器，那一帧 17–59 毫秒。原因与改法：
    - `renderer.compile` 编不到投影那一遍。
    - 先试过「离屏真渲一帧」，结果 three.js 按离屏目标的输出（不调色、线性）把整个场景的 110 多个材质又编了一套。
    - 也试过直接调用阴影那一遍，但离开正常渲染时它用不了（载入失败）。
    - 最后改为：预热后真画的那一帧里，把会投影的演出物放到镜头下方 200 米、颜色深度都不写地显示一帧。着色器变体随场景灯数而变，满蓄力那一刻再预热一遍。
    - 实测演出中不再编着色器。
    - 这套预热的第一版又带出两个问题，自检时发现、已修好：
      - 两个轴头共用一份材质，第二次记到的是已经关掉的值，收回后轴头一直不画；
      - 预热还没收时再次预热（换场景），会把「正在显示」当成原状。
    - 改法：每份材质只记一次；预热前先收回上一次。`r25_full.mp4` 是改后重录的。
12. **自检本身的问题**：
    - 空挥测试里残留的敌人；
    - 取到旧的出刀记录（改按招式号过滤）；
    - 旧的处决记录被当成新的；
    - 悬崖测试站到了台阶下；
    - 墙边测试的位置；
    - 帧率测试的取样窗口与事件记录上限；
    - 舍入容差；
    - 保护测试在第三十层里开始（改为先回宗门）。
13. **录像里墙边没有走精简演出**：没锁定目标时，蓄势会转向侧面镜头所看的方向（转了 66°）。换了轴线之后，偏 50° 的完整路线是合法的，所以放了完整演出——这是规则本身。墙边录像改为锁定目标（见 §10 第 1 条）。

## 10. 没做完、没改、需要注意的

1. **墙边不一定精简**：需求要求「正对的轴线不合法时换偏角再试」。所以墙边只要有一条偏 25° / 50° 的路线合法，就放完整演出。试拍时没锁定目标，人朝侧面镜头转了 66°，偏 50° 的路线就合法了。录像里锁定了目标，正对墙走，因此是精简。
2. **满蓄力那一刻可能小卡一下**：每到一个新的灯光配置（换地方、入夜后近处亮灯），第一次满蓄力时会编一个投影着色器，约 14–16 毫秒。这是为了让演出里不卡，把它挪到了蓄力的那一刻；同一处再蓄力就不再有。
3. **鞘口墨环在正常视距下很小**：近看清楚；平时主要靠墨势签与终式格子提示。
4. **凤鸣、龙吟在混音里偏轻**（峰值约 −21 dBFS）：是有意压在收刀清响之下，可在 `inkFinale.js` 里调大（现为 0.42 / 0.34）。
5. **剧情保护的验收**：用第三十层的 `noDmg`（开战前、过场中、阶段交接时都是它）代表剧情保护。游戏里没有别的剧情保护类型。
6. **性能数字**：来自后台标签页，起伏较大，只适合看同一次里演出与场景本身的相对量级。前台真机的帧率请再实测。
7. **大型目标的精简演出**：第五十层的龙君很大，镜头拉得较远，演出的笔画显得小。
8. **合成音轨的混响**：游戏与离线渲染都用随机生成的冲激响应，所以录像里的混响尾巴与游戏里不会逐样本相同。
9. **素材授权**：本轮没有新素材。凤凰、雷龙模型与第二组水墨贴图的授权问题见 README「素材来源与授权」（第二十一、二十三轮的说明）。
10. **没有多人联机**：演出只按单人设计（需求如此）。
